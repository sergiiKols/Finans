# kabinet — семейный учёт на домашнем ПК

Локальный сервис: запускается на домашнем компьютере, открывается в браузере,
наружу ничего не отправляет. Заведён 17.08.2026 по решению владельца — Windows,
доступ вне дома не нужен, пользуемся дома.

Устроен как `/root/transfer/transfer.py`: **чистая стандартная библиотека Python,
ноль зависимостей.** Ставить нечего, кроме самого Python.

## Как запустить на Windows

1. Скопировать на ПК папку `chartaev` целиком — нужны `kabinet/` и `yadro/`
   (в `yadro` живёт расчётное ядро и правила).
2. Поставить Python с python.org, **отметив галочку «Add Python to PATH»**.
3. Двойной клик по **`Кабинет.bat`** — откроется браузер на `localhost:8090`.
4. Первый заход: «Состав» → завести участников → «Записать» → вносить операции.

Окно консоли не закрывать: пока оно открыто, кабинет работает.

**Телефоны в домашней сети** — запускать `Кабинет-для-телефонов.bat`. Он покажет
адрес компьютера, Windows спросит разрешение брандмауэра (ответить «Разрешить»,
галочку «Частные сети» оставить). С телефона заходить по `http://адрес-ПК:8090`.
В роутере имеет смысл закрепить за компьютером постоянный адрес, иначе он меняется.

## Связи в семье задаёт родство, а не возраст

**Исправлено 17.08.2026 по замечанию владельца:** сначала кандидатами в родители
предлагались все взрослые. Это неверно — взрослая дочь и бабушка взрослые, но
родители ребёнку не они.

- Родителем может быть только участник с родством **отец** или **мать**, и таких
  двое, сколько бы взрослых ни было в составе.
- У сына и дочери — поле **«Родители»**; при выборе родства оно заполняется само.
- У бабушки и дедушки — своё поле **«Чей родитель»**: связь с отцом или матерью.
  Так выстраивается цепочка поколений без матрицы «каждый с каждым».
- Проверка не даёт сохранить состав, где двое отцов, две матери или у ребёнка не
  отмечены родители.

Возраст по-прежнему решает только одно: кто взрослый и кто делит общие затраты.

## Разделы: по частоте, а не по устройству модели

В шапке каждого экрана шесть разделов, текущий подчёркнут:

**Сегодня** (`/`) — состояние и действия, сюда заходят чаще всего ·
**Записать** — ввод факта · **План** — ожидаемое по нижней границе ·
**Месяц** (`/mesyac`) — прежний полный отчёт: субсчета, фонды, распределение,
сверка · **Что если** (`/chto-esli`) — песочница модели ·
**Счета** — где физически лежат деньги · **Состав** — кто участник.

Модель не спрятана, она опущена уровнем ниже: с «Сегодня» в неё ведёт первая же
карточка блока «Почему столько». Разбор, почему так, —
[`../razbor-polzy-2026-08-18.md`](../razbor-polzy-2026-08-18.md).

## Как найти ввод

Текущий раздел подчёркнут. На месяце без записей отчёт не ругается ошибкой, а показывает,
с чего начать, и ведёт кнопкой в нужный раздел.

## План и распределение в реальном времени (вариант Б)

Поступления приходят раз в неделю, а норма накопления у нас прогрессивная — доля
первой недели зависит от того, что придёт в четвёртую. Поэтому:

1. **План месяца** — ожидаемые поступления по участникам и обязательные траты по
   статьям. Планировать **по нижней границе ожидаемого**: тогда корректировка при
   закрытии идёт в приятную сторону, в фонды доперечислим. Обратная хуже — деньги
   уже могли уйти на еду.
2. **Каждое поступление делится сразу** на три доли: в накопление (по плановой
   норме), отложить на обязательное (доля прожиточного минимума), свободные.
   Экран ввода показывает разбивку до записи и подсказывает, сколько перевести
   на накопительный счёт.
3. **Закрытие месяца** — блок «План и факт» в отчёте: доход, обязательные траты,
   норма, отчисления. Последняя строка — **корректировка**: довнести в фонды или
   вернуть в потребление.

Пример проверки: план 3 000, факт 4 400 → норма поднялась с 36,9 % до 50 %,
по плану отчислено 1 624,04, по факту должно 2 200,20, **корректировка +576,16**.

## Учётные счета и денежные — разные вещи

Семь субсчетов **учётные**. Физически деньги лежат в одном-двух местах: текущий
счёт и накопительный. Кабинет говорит, сколько перевести; перевод делает человек
одним действием в банке. Заводить семь настоящих счетов не нужно.

Банковского API для физлиц нет — это проверено, а не предположение: то, что банки
называют API, работает по договору с юрлицами. Поэтому сверка с банком делается
по выписке, а не автоматическим списанием.

## Главное правило устройства

**В базе лежат факты, а не посчитанные числа.** Кто, когда, за что, сколько.
Доли, паи, фонды и дефицит считаются заново ядром `yadro/raschet.py` при каждом
открытии отчёта.

Поэтому изменение правила ничего не портит: поменяли норматив, минимум взноса или
тариф — пересчитали, история осталась. Это же значит, что кабинет всегда согласован
с журналом решений `RESHENIYA.md`: правила в одном месте, а не продублированы в базе.

## Типы операций

| Тип | Когда | Что заполняется |
|---|---|---|
| Деньги извне | зарплата, подработка | кому, сумма, за что |
| Обязательная трата | еда, коммуналка, электричество | статья, сумма |
| Оплата внутри семьи | работа по дому, урожай | кто платит, кому, сумма |
| Выплата из фонда | учёба, лечение, оценки | из какого фонда, кому, сумма |

Обязательные траты складываются в **прожиточный минимум месяца** — от него ядро
берёт ступени шкалы накопления (Р-15). Подорожала коммуналка — норма накопления
снизилась сама.

## Контроль счетов

Раздел **«Счета»** — реестр того, где физически лежат деньги: текущий счёт,
накопительный, наличные. У каждого остаток и ставка годовых, галочкой отмечаются
те, где хранятся накопления семьи. Остатки вводятся руками — банковского API для
физлиц нет, зато обновлять их надо раз в неделю, когда делаете перевод.

Справа — **сверка с учётом**: сколько накоплено по расчёту (имущественные паи всех
месяцев плюс остаток фондов) против того, что реально лежит на накопительных счетах.
Три исхода:

- **сходится** — переводы сделаны, учёт совпал с банком;
- **на счетах больше** — обычно личные деньги лежат там же либо поступление ещё не записано;
- **на счетах меньше** — часть накопленного не переведена или потрачена, надо разобраться.

Ставка нужна не для красоты: с неё считается доход на имущественный пай (Р-9),
и он начисляется **только с реально размещённого**.

## Если имена в журнале и в составе разошлись

Кабинет считает по составу семьи. Если операция записана на «папа», а в составе
«Сергей», раньше такая запись **молча выпадала из расчёта** — выручка обнулялась,
и отчёт показывал дефицит на ровном месте. Теперь такие имена собираются отдельно
и называются прямо в сообщении: «в журнале есть записи на людей, которых нет в
составе: … — поправьте состав или записи».

## Чем платите за домашний ПК

- Вне дома не работает. Пробрасывать ПК в интернет не надо — это дверь в домашнюю сеть.
- ПК выключен — учёта нет.
- Резервные копии делает сам при запуске, но лежат они на том же диске.
  Раз в месяц копировать `uchet.db` на флешку или на сервер — это на вас.

## Если что-то не так

- **«Python не найден»** — не отмечена галочка «Add Python to PATH» при установке.
- **Порт занят** — запустить `python server.py --port 8091`.
- **Состав не заведён / нет поступлений** — отчёт честно скажет об этом вместо чисел.
- **«Расчёт остановлен»** — сработало правило Р-13: четвёртый месяц подряд с
  непокрытым дефицитом. Это не поломка, а требование решения человека.
- **Начать с чистого листа** — удалить `uchet.db` (сейчас в ней лежит август 2026).


## «Что если» — песочница модели

Раздел заведён 18.08.2026 по запросу владельца: надо было видеть, как модель
ведёт себя при разных числах, а не только на одном записанном месяце.

**Что можно крутить.** Ползунком и полем: зарплата и подработка каждого
участника; сколько семья платит своим за дела по дому, урожай и оценки;
каждая обязательная трата и карман; полная норма накопления; и главное —
**правило деления общих затрат**, пять вариантов.

**Что показывает.**

- **Накопление и потребление** — кольцо главного деления по Чартаеву: вся выручка
  семьи делится на фонд накопления и фонд потребления, в рублях и процентах.
  В раскрытии — семь именных субсчетов, из которых сложился фонд накопления.
- **Куда ушёл доход извне** — второе кольцо, только реальные деньги: на руки,
  обязательные затраты, имущественные паи, остаток в фондах.
- **Что это значит** — окупает месяц обязательное или нет, норма, минимум.
- **Каждому** — выручка, его доля затрат, на руки, пай.
- **Пять правил на этих же числах** — таблица «на руки» у каждого участника при
  каждом из пяти правил деления общих затрат, с размером непокрытой дыры.

**Ничего не записывается.** Расчёт идёт через `POST /api/chto-esli`, ядро
`R.schitat` читает нормативы и не пишет ни в базу, ни в файлы. Закрыли вкладку —
следа не осталось. Числа при открытии берутся из настоящего месяца
(`/api/chto-esli/zagotovka`), чтобы было видно, какое изменение что сдвинуло.

**Проверено.** Песочница на числах августа даёт ровно то же, что настоящий
расчёт: на руки 64,90, паи 22,63, фонды 12,46, непокрыто 115,90 — совпадение
до копейки, то есть это то же ядро, а не вторая модель. Живой пересчёт снят
браузером: 1 500 → норма 2,4 % и дефицит; 6 000 → норма 50 %, месяц окупается;
еда 3 000 при тех же 6 000 → норма сама падает до 25,7 %, потому что ступени
шкалы считаются от прожиточного минимума (Р-15). Ошибок в консоли нет.

## Разработка на сервере

На сервере кабинет поднят службой `kabinet.service` — порт **8772**, только
`127.0.0.1`, база `/root/chartaev/kabinet/uchet.db` (отдельная от домашней).

    systemctl status kabinet     # состояние
    systemctl restart kabinet    # после правки server.py или экранов
    journalctl -u kabinet -n 50  # что вывел сервер

Смотреть из дома — **через уже работающий туннель дашборда**, второй порт
пробрасывать не нужно:

    http://localhost:8770/uchet/

Дашборд (`/root/transfer/transfer.py`) проксирует всё, что начинается на
`/uchet`, на 127.0.0.1:8772 и вставляет в начало `<head>` строку
`window.PREFIX="/uchet"`. Экраны читают её в переменную `PRE` и строят от неё
все ссылки и запросы, поэтому один и тот же файл работает и по прямому адресу
(дома `localhost:8090`, на сервере `localhost:8772`), и под префиксом.

Переменная названа `PRE`, а не `P`: на экране плана `P` — это объект плана,
и совпадение имён валило страницу с «Identifier 'P' has already been declared».

Прямой доступ тоже жив, если пробросить порт:

    ssh -L 8770:127.0.0.1:8770 -L 8772:127.0.0.1:8772 root@91.186.210.250

**Две базы — два учёта.** Серверная нужна для проверки экранов и расчёта,
семейные записи ведутся дома. Перенести домашнюю на сервер — скопировать
`uchet.db` и перезапустить службу.

## Кабинет понимает оба адреса

Один и тот же сервер отвечает и на `/vvod`, и на `/uchet/vvod`: префикс
снимается в `_snyat_prefiks()`, а в HTML подставляется `window.PREFIX`, чтобы
ссылки остались под тем же префиксом. Сделано после того, как туннель, ведущий
прямо на порт кабинета, получал на адресах вида `/uchet/plan` ответ
«нет такой страницы» — теперь неважно, куда проброшен порт.

## «Что если»: пересчёт по кнопке

Раздел `/chto-esli` считает не на каждое движение ползунка, а по кнопке
«Пересчитать» (или `Enter` в поле). Так сделано после того, как при работе
через SSH-туннель очередь запросов вешала вкладку. Пока есть непосчитанные
изменения, внизу экрана висит полоса с этой же кнопкой.

Единственное действие, ради которого экран открывают среди месяца:

> **записал за неделю → увидел, сколько перевести → перевёл → отметил.**

**Как считается.** Не по календарным неделям, а нарастающим итогом:
записанный с начала месяца доход × доля накопления − уже переведённое.
Пропустили неделю — число просто больше. Перевели лишнего — уйдёт в «с запасом»
и уменьшит следующий перевод. Недельных границ нет намеренно: норма накопления
прогрессивная, её нельзя честно нарезать на семидневки.

**Доля берётся из плана месяца** (Р-16, «вариант Б»): норма зависит от месячного
итога, а он в середине месяца ещё не наступил. Плана нет — считаем по факту и
пишем об этом прямо на экране: такая доля занижена, при закрытии придётся доложить.

**Перевод не попадает в журнал операций — и это главное правило здесь.**
Перемещение денег между своими счетами не выручка и не затрата: ядро о нём не
знает и знать не должно, иначе один рубль посчитается дважды. Отметка живёт в
таблице `perevody` и двигает только остатки счетов — в банке они уже сдвинулись.
Отмена возвращает всё на место.

**Что можно поправить руками.** Сумму (банк округляет, человек переводит «ровно
50») и счёт-источник: кабинет предлагает самый полный из не-накопительных, но
знает про деньги только то, что ввели на «Счетах».

| Ручка | Где |
|---|---|
| `GET /api/perevod?mesyac=` | сумма, из чего сложилась, счета, список отметок |
| `POST /api/perevod` | отметить: `{summa?, so_scheta?, na_schet?, data?}` |
| `POST /api/perevod/udalit` | отменить: `{id}` |

Проверяется прогоном `proverka-perevoda.py` — шесть инвариантов, включая
«журнал операций не тронут».
